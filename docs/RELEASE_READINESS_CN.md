# Evo 上线准备清单（中文）

> 本文区分“CI 已验证”和“仍需真实部署验证”。CI 通过不代表系统已经可以直接对外营业。

## 当前已验证

- [x] Python 回归测试工作流可运行：`python -m unittest discover -s tests -v`。
- [x] Admin UI 工作流执行 `npm ci` 与 `npm run build`（包含 `vue-tsc` 类型检查与 Vite 构建）。
- [x] Mission planner 为节点输出结构化 `decision_trace`，使用稳定规则 ID 与可机器读取证据。
- [x] 规划追踪在 mission run plan 与 action 记录中的传播有回归测试。
- [x] 自动续跑有重复触发保护，并记录启动失败原因。
- [x] 任务详情 UI 有规划决策追踪展示入口。

## 上线前必须完成

### P0：部署安全与数据可靠性

- [ ] 生产环境密钥检查：`SESSION_SECRET` 必须由部署环境显式提供，禁止使用示例/默认值。
- [ ] 确认 Cookie、安全头、反向代理 HTTPS、CORS、登录态和权限边界。
- [ ] 确认工作目录、数据库/JSON 状态、上传文件与日志的持久化、备份和恢复步骤。
- [ ] 检查日志、异常和追踪字段不会写入 Token、密码或不必要的个人信息。
- [ ] 在目标部署环境验证健康检查、进程重启、磁盘空间与任务队列恢复。

### P0：端到端业务验收

- [ ] 创建 mission → 生成 plan → action/dispatch → worker 执行 → 交付物 → 验收/失败 → 学习单/经验，逐环核对关联 ID 与状态。
- [ ] 覆盖缺输入、无匹配能力、worker 失败、超时、重复刷新、自动续跑失败等场景。
- [ ] 验证追踪缺失或格式异常时页面降级展示，不影响任务主流程。
- [ ] 用真实业务工种执行至少一条成功任务和一条失败恢复任务，人工核对结果真实性。

### P1：发布与运维

- [ ] 在干净环境从头部署，按部署文档验证安装、配置、升级和回滚。
- [ ] 检查外部依赖、Git/Gitee 授权、网络失败和限流时的错误提示与重试策略。
- [ ] 进行基本并发/长任务测试，检查任务状态是否会卡在 running。
- [ ] 明确首发范围、已知限制、数据保留策略、告警和故障处理责任人。
- [ ] 先内部试运行，再小范围灰度；确认无阻断问题后再扩大使用。

## 当前进度口径

截至本清单编写时，自动化回归与前端构建已通过；这只覆盖代码级检查。真实部署安全、备份恢复、外部集成与完整业务端到端流程尚不能仅凭 CI 判定通过。

建议按“P0 全部通过 → 内部试运行 → 小范围灰度 → 正式发布”推进。若现有部署环境与核心业务流程已经具备，预计还需约 **1–2 周**完成首发验收；若发现权限、持久化、外部授权或任务状态等阻断问题，时间应按修复与复测结果重新估算。此估算是计划区间，不是上线承诺。
